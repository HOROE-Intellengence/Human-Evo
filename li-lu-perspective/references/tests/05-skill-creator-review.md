# Phase 5 Agent B：skill-creator 评审

评审对象：`SKILL.md`（420 行）  
评审原则：发现成本低、触发精确、正文只保留会改变决策的非显然指导、避免把测试特例固化成普遍规则、支持渐进披露。  
本报告只给修改建议，不改 `SKILL.md`。

## 结论

这个 Skill 已经能用，人物边界、知识诚实、持仓沉默和不冒充未公开信息都写得扎实。主要问题不是缺内容，而是入口与正文的资源分配不够经济：

1. **触发条件基本正确，但仍有轻微错位。** description 中“用于价值投资、长期决策、职业与组织判断”是宽用途词，可能抬高普通问答误触发率；另一方面，真实用户更常说“按李录的方法分析这家公司”“用李录框架审视”，当前触发例只覆盖了“视角 / 会怎么看 / 模式”。
2. **角色规则可执行，Agentic Protocol 过长且重复。** 第 26—111 行共 86 行，约占正文五分之一；A—D 研究清单与后面的六个心智模型、九条启发式大量重合。固定六步输出也容易让短答机械化。
3. **references 存在但发现太晚。** 入口直到附录才笼统说“见 `research/`、`synthesis.md`”，没有告诉执行者遇到引用核验、立场更新、争议审查时分别读哪个文件。现有研究材料超过 2,000 行，不做路由就很容易全读或完全不读。
4. **有一处明显把边缘测试写成普遍规则。** “新技术被赋予代理权、投票权、资金权限或正式治理身份……”是单类 AI/治理场景，不应成为所有“新技术或未知领域”的固定检查项。另有两条轻度过约束：“关键事实或招牌判断至少附一个出处”会让纯框架回答也被迫加引用；“每次回答最多一个笑点”不是影响判断质量的必要约束。

## 建议 1：重写 description，让“人名 + 明确调用意图”成为触发门槛

**优先级：高。** 这是最便宜、最直接的防误触发改动。删除来源数量和模型数量——它们不帮助发现，还会在材料更新后变陈旧。把宽泛用途改成“只有明确提到李录并要求应用框架时触发”。

建议将 frontmatter 中的 `description` 整段替换为：

```yaml
description: |
  用李录（Li Lu）的公开思维框架分析价值投资、企业、长期决策、组织激励与职业选择。当用户明确提到李录 / Li Lu，并要求“用他的视角或框架分析”“按他的方法审视”“他会怎么看”，或明确调用本 Skill 时使用。不要仅因问题涉及价值投资、能力圈、安全边际或中国市场而自动触发。
```

这会覆盖真实说法，同时避免普通的“这只股票能买吗”“如何做价值投资”自动进入角色。

## 建议 2：把角色规则与 Agentic Protocol 合并成短路由；领域清单按需下沉

**优先级：高。** 保留会改变行为的约束：首次免责声明、知识路由、当前事实先核验、未公开立场标推断、持仓沉默、事实 / 推断 / 未知可分辨。删除重复的 A—D 展开和固定六步格式；如确实需要领域检查表，将现有 A—C 和精简后的 D 移到 `references/research-playbook.md`，只在对应任务时读取。

建议用下面文本替换当前“角色扮演规则”与整个“回答工作流”两节：

```markdown
## 操作规则

激活后，以第一人称运用李录的公开思维框架。首次只说明一次：“我用李录的公开思维框架和你讨论；这是基于公开资料的模拟，不代表本人。”

- **先路由问题**：纯框架问题直接回答；涉及具体公司、人物、事件、政策、技术、日期或数字时，先核验会改变结论的事实；混合问题先核验案例，再应用框架。
- **先校准知识边界**：把关键变量分为知道、不知道、不必知道和未知的未知；证据不足就降低确信度或归入“太难”。
- **区分本人立场与框架推断**：李录没有公开表态的主题，明确说“这是框架推断，不是本人公开立场”。
- **保留结构性沉默**：不推测 Himalaya 的当前持仓、目标价、具体买卖点、净值、费率、风控、交易或内部意见；改为说明判断方法。
- **避免投资背书**：分析具体证券时讨论永久损失、安全边际、反方与失效条件，不替用户下单。
- **引用按需**：只有结论依赖外部事实、当前信息或直接引语时，才在相关结论旁给极简出处；纯框架回答不为装饰强加引用。
- 用户说“退出”“切回正常”或“不用扮演了”时，恢复正常模式。

## 回答路由

需要研究时，优先使用监管文件、公司原始披露、官方统计、完整访谈和本人材料；新闻摘要只作线索，社交媒体情绪不作核心证据。具体公司、国家 / 政策、职业 / 组织或新技术的检查项，按需读取 [research-playbook.md](references/research-playbook.md) 的对应小节，不要一次加载全部。

回答前在内部区分：**事实、推断、反证、未知、失效条件**。默认输出顺序是：

1. 直接判断与确信度；
2. 真正决定结果的机制；
3. 必要证据；
4. 最强反方或失效条件；
5. 行动含义：研究、等待、放弃、改结构，或在安全边际充分时行动。

这是默认骨架，不是强制模板。短答只用“判断 → 一个理由 → 一个边界”，不要硬塞文明史、表格或固定数量的分点。
```

`research-playbook.md` 中的新技术部分建议只保留三条通用规则：区分可验证能力、商业化假设与远期外推；核验真实数据和责任链；区分可逆错误与不可逆尾部风险。删除“投票权 / 资金权限 / 正式治理身份”整句，除非未来专门增加 AI 代理治理模式。

同时删除“每次回答最多一个笑点”。保留“少量干幽默、不嘲弄他人”即可；笑点计数既难执行，也不会提高李录式判断质量。

## 建议 3：把附录改成按任务路由的证据索引

**优先级：中。** 当前附录重复列举来源和三条引语，却没有说明何时读取哪份材料。用下面短索引替换“附录：调研来源”全节，可减少重复并让关键 reference 在需要时被找到：

```markdown
## 证据与更新路由

按当前任务读取，不要默认加载全部材料：

- 调整或审计心智模型、启发式和核心张力：读 [synthesis.md](references/synthesis.md)。
- 核验著作观点或直接引语：读 [01-writings.md](references/research/01-writings.md)，必要时回到 [sources](references/sources/) 中的原文。
- 模拟问答路径或表达风格：分别读 [02-conversations.md](references/research/02-conversations.md) 与 [03-expression-dna.md](references/research/03-expression-dna.md)。
- 检查批评、争议、利益冲突或反证：读 [04-external-views.md](references/research/04-external-views.md)。
- 核验重大决策、投资案例或 13F 边界：读 [05-decisions.md](references/research/05-decisions.md)。
- 更新人物经历、机构角色和近期动态：读 [06-timeline.md](references/research/06-timeline.md)，并重新核验调研截止日之后的事实。

调研截止：2026-08-20。此后事实不得沿用为当前事实。
```

底部创建者归属可以保留。身份卡、六个模型、启发式、表达 DNA 和诚实边界也应留在入口文件；它们是每次激活都会改变判断的核心，不建议为了追求短而全部外移。

## 应保留的内容

- “不推测 Himalaya 未公开信息”是这个人物 Skill 的关键防幻觉边界，必须保留。
- “停止做空是个人能力、注意力和基金结构判断，不否定擅长做空者”成功阻止了把个案写成普遍戒律，应保留。
- “宏观定边界、微观下注”“所有者天线”“知识诚实四象限”是可生成新判断的模型，不是人物资料堆砌，应继续放在 `SKILL.md`。
- 最新动态与 13F 的限制说明有用，但完整时间线可在后续进一步下沉到 `06-timeline.md`；入口只留调研截止日和当前身份即可。

## 推荐执行顺序

先改建议 1，再改建议 2，最后改建议 3。三项互不冲突；预计可把入口压缩约 90—120 行，同时提高触发精度和按需读取能力，不损失人物辨识度。
